## M1现场逐步命令

M1-1若要逐个Ctrl+C停节点，先停止chain/dual，再在三个分别source环境并设置ROS_DOMAIN_ID=71的终端各运行一条：

```bash
ros2 run smartcar_training node_a_sensor
ros2 run smartcar_training node_b_filter
ros2 run smartcar_training node_c_alarm
```

第四终端检查契约、调参数与手动服务：

```bash
ros2 interface show sensor_interfaces/msg/SensorData
ros2 topic hz /processed_distance
ros2 param set /node_b_filter alpha 0.9
ros2 param set /node_c_alarm alarm_threshold 0.5
ros2 service call /trigger_alarm sensor_interfaces/srv/TriggerAlarm \
  '{distance: 0.1}'
```

为确保停B后还有报警触发条件，先把C的alarm_threshold设5.0，再Ctrl+C停B，1秒无响应后应出现报警服务超时；结束后恢复0.3。无效帧演示时保持B运行、停A，在第四终端执行下列命令；B打印status=1警告，不新增滤波输出：

```bash
ros2 topic pub --once /sensor_data sensor_interfaces/msg/SensorData \
  '{distance: 0.01, unit: m, status: 1}'
# M1-2: deliberate missing-YAML check; do not leave duplicate groups running
ros2 launch smartcar_training bringup.launch.py \
  namespace:=robot1 params_file:=/tmp/smartcar_missing.yaml
```

C的实际参数名是alarm_threshold，不能写成threshold。以上是本人现场操作步骤；实际停服务与无效帧逻辑已由完整契约检查器验证。

## M3

只运行一个Gazebo实验。M3方形/建图与导航使用不同domain/通信环境，按脚本运行，不混用终端。

```bash
# 方形短演示；已有十次统计单独展示
bash scripts/run_m3_demo.sh square
# 原生map_server + 实际RViz；保持PGM/YAML不变
.venv-ros/bin/python scripts/run_m3_map_demo.py --seconds 90
# 完整巡场并录制真实/map、TF应用窗口；不替换正式导航地图
bash scripts/run_m3_demo.sh mapping --no-promote --viewer
# 实际RViz中按G，在自由区拖出目标位置与朝向，等待该次结果
bash scripts/run_m3_demo.sh target
# 坐标输入路线仍保留，输入是地图坐标x,y,yaw（弧度）
bash scripts/run_m3_demo.sh static --goal 10,5.5,1.5707963268
# 默认按实际/odom首次超过0.02m/s或rad/s后3秒生成实体障碍
bash scripts/run_m3_demo.sh dynamic
# 临时世界坐标。两次尝试均保留，每次清理后再起下一次
bash scripts/run_m3_demo.sh dynamic --obstacle-at 9.2,1.3 --runs 2
# 边界：箱子覆盖默认世界目标，须失败并停车，不计入可达成功率
bash scripts/run_m3_demo.sh dynamic --obstacle-at 11,5 \
  --obstacle-size 0.8 --timeout 90
```

RViz的SetGoal工具写`/smartcar/exam_goal`，独立试验器接收后转成NavigateToPose并记录实际点击目标，避免与Nav2默认`/goal_pose`订阅产生双重发目标。目标必须为map帧与有限归一化姿态。目标不按预置坐标覆盖。

`dynamic`的一键演示现显式选择`motion`计时，`result.json`保存首次运动、注入起点及实际延迟。底层批量试验器默认仍为`accepted`，用于保留旧版批次口径；当前run_benchmark显式使用motion并采集46次匹配参考与动态试验。可以显式`--injection-reference accepted`复现旧方式；两类批次不能混算。

SLAM录像是实际应用窗口，订阅实时SLAM地图与TF，不读取真值修图。独立RViz步骤显示原生map_server输出；窗口截图需目视核对确有地图，不能把黑色渲染区域作为展示通过证据。

## 验证顺序

1. 构建后跑M1全验收、新双组launch、逐点查询点击和独立bag对应核对。
2. 完成原图RViz加载；录一次当前真实SLAM巡场，检查地图更新、TF与视频可读，保留正式图哈希。
3. 实际RViz指定新目标跑两次，保留输入消息、图像、终点与原始日志。
4. 新障碍位置跑两次并核对确实影响实际路径；按运动计时的注入延迟可核查。
5. 当前2cm配置下复现目标占据边界，区分Action失败与试验器看门狗，检查停车和几何间距。
6. 当前验收矩阵已用实际结果更新；部署验证、最终Git提交与离线交付的校验值由交付清单记录。

## 投影现场TF查询的通信域

一键链路/双组使用ROS_DOMAIN_ID=71；一键投影脚本独立使用64。投影窗口运行时，另开终端依次执行source scripts/env.sh、export ROS_DOMAIN_ID=64，再执行ros2 run tf2_ros tf2_echo camera_link laser_link。两个外参运行之间会重启，TF查询可保留或重启；不要在71域查询64域的投影。
