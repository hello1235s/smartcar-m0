# M3-4：动态障碍对照

```bash
source scripts/env.sh
.venv-ros/bin/python M3/M3-4/scripts/run_benchmark.py --runs 10 --obstacle-at 8.0,1.6 --delay 3.0 --obstacle-size .6
```

三组同一RPP的参数：A为0.28m/s、0.7m前视、2s碰撞预测；B为0.65m/s、0.25m前视、0.5s预测；B_tuned将B改为0.45m/s、0.5m、1.5s。地图、车体、目标相同。速度仍受公共平滑器和底盘限制，记录的是实际下发给控制器的带时间戳命令。

每次Action目标被接受3秒后通过Gazebo spawn服务生成0.6m实体，激光可见且能发生物理碰撞，未直接写代价地图。初版(9,1)离原路径约0.59m，不能证明真正避障，明确不计入有效比较；新位置(8,1.6)基于无障碍规划轨迹选择。位置、尺寸和时机均为CLI参数。

每个有效尝试都有result.json、轨迹CSV、实际转向命令及全局plan时序。最终四指标：成功次数/10；仅成功样本平均耗时；基于匹配无障碍参考的/plan规划绕行估计；实际中心转向角变化总量除路径长度(rad/m)。规划绕行口径详见report.md，不把规划估计当成实际里程。另保留odom积分差作辅助；B没有成功的匹配无障碍到达样本时该项为null。没有成功样本时均值为null，不用失败耗时或0冒充成功指标。

批次manifest关联各组原始目录；基础设施失败、导航失败和旧位置试验分别保留。调优后同样跑10次。二维过程图为真实ROS map/plan/scan/TF查看器的窗口截图，不冒充Gazebo三维渲染。首次截图退出清理有问题，已补充SIGTERM处理及超时兜底，避免孤儿仿真污染后续批次。

最终原始数据、对比图、失效边界及重规划延迟见 results/ 和report.md。注入到下一plan的延迟与“控制失败后重规划延迟”是不同指标，报告分别给出，不混用。
