# M0-3：传感器数据清洗与问题报告

**运行**

```bash
cd ~/smartcar-m0
source .venv/bin/activate
python M0/M0-3/sensor_analyzer.py --input M0/M0-3/sensor_data.csv --output M0/M0-3/cleaned_data.csv
python -m pytest M0/M0-3/tests -q
```

也可进入 `M0/M0-3` 后无参数运行 `python sensor_analyzer.py`。
默认输入、默认输出都相对于当前工作目录；显式输出父目录应事先存在。
输入 UTF-8 CSV 必须有 `time,value` 两列；允许额外列，数值必须有限。
输出保持输入顺序，每行保留原来配对的 time、value；时间和值以浮点数写出，文本小数位数可能变化。

**原始代码的八类缺陷**

下面的行号以题目原始 `sensor_analyzer.py` 为准，可以在根提交中对照。

| 缺陷 | 原始位置与现象 | 原因与修复 |
| --- | --- | --- |
| 1. 列名大小写错误 | 第 37 行读取 `row["Value"]`，立即 KeyError | CSV 实际列名为小写 `value`；改正并先验证表头 |
| 2. 标准差公式错误 | 第 52～53 行，标准差几乎为 0 | 偏差直接相加会相互抵消；改为平方偏差和除以 N 后开方，最终用 hypot 稳定计算 |
| 3. 遍历时修改列表 | 第 56～58 行，删除后相邻元素可能被跳过 | 原地 remove 改变迭代位置；改为生成新的筛选列表 |
| 4. 只筛选上侧异常 | 第 57 行只判断大于上界，低值异常保留 | 使用 `abs(value - mean) <= 2 * std` 保留正常值，等于边界也保留 |
| 5. cleaned 从未赋值 | 第 28、66 行，输出只有表头 | 原代码始终写出空列表；将筛选结果实际赋给 cleaned |
| 6. 时间与输出列丢失 | 第 66～67 行，仅写 `[v]`，不能对应 time,value 表头 | 保存并筛选 `(time,value)` 整条记录，再写两列，避免时间错配 |
| 7. 输出路径写到根目录 | 第 61 行构造 `/out/cleaned_data.csv`，目录不存在或无权限 | 使用调用方提供的输出路径，默认当前目录，无硬编码根路径 |
| 8. 文件句柄管理不完整 | 第 33、62 行 open 后未正确关闭 | 输入输出都使用 with，保证异常时也关闭文件、正常结束前刷新输出 |

此外补充了空文件、缺列、重复列名、非数值、非有限数值、损坏 CSV、缺文件和输入输出同路径校验；
错误打印至 stderr，退出码为 2，无裸露栈回溯。成功退出码为 0。单条数据和恒定值数据标准差为 0，全部保留。

**真实排查顺序与结果**

先记录原始 KeyError，改正字段后暴露 `/out` 路径错误；修正路径后脚本能退出，但 std≈0、cleaned=0。
再修标准差，数值变为 18.5033，cleaned 仍为空；最后修复筛选和配对输出。
各阶段日志在 `evidence/m03_*.log`，对应改动保留在 Git 中。

对原始全集只做一次统计和筛选，使用总体标准差（分母 N），不是样本标准差（N−1），也不是反复迭代清洗。
控制台 mean/std 表示清洗前原始数据的统计量。

```text
共读取 60 条数据
均值 mean = 50.4315366667
标准差 std = 18.5032794933
清洗后剩余 57 条；剔除 3 条
```

剔除的三个 value 为 118.4、132.7、−21.3。结果已与 NumPy `mean`、`std(ddof=0)` 和独立筛选对照。
17 项测试覆盖样例、相邻双侧离群值、时间对齐、输入不变、零标准差、错误输入及两种命令行调用方式。
独立实现一致不代表已经通过现场新数据考核。
